# V0.1 family pilot

Status: prepared for testing, **not yet validated with a real household**. Main publishes development prereleases; passing CI does not declare a stable V0.1.

## Installation and preparation

Use the native executable with [systemd](../deployment/systemd.md) and [Tailscale private HTTPS](../deployment/tailscale.md). Docker is optional future work. One process owns each persistent data directory. Keep the exact Documents `.hap` package and an encrypted backup outside the VM.

The pilot needs an owner and one consenting household member, using two separate browser sessions. The owner creates an invitation or prepares assisted PIN access from **Mi familia**; do not share the owner's account. Give the second member only the permissions needed for the trial. Confirm both devices can reach the private origin through the tailnet before handing over an invitation.

Start with synthetic files. Once recovery has been checked, choose a few ordinary, low-sensitivity household documents. Do not use this experimental installation as the only copy of important originals. Keep backup passwords separately from archives. Never attach credentials, invitation links or private documents to bug reports.

## Tasks for each person

| Task | Expected result |
| --- | --- |
| Open private HTTPS and sign in | Correct household and name; a different browser needs its own login or PIN binding. |
| Open Mis módulos → Documents | Only active, authorized modules appear. |
| Upload one PDF, PNG, JPEG and TXT | Original downloads match; metadata can be edited by the owner of the document with write permission. |
| Search from Buscar, then select Documents | Title, description and tags are searchable. URL preserves the query and module. File contents and OCR are not searched. |
| Share one file with the second person | Recipient can find, read and download it; private files remain absent. Sharing does not grant editing or resharing. |
| Remove sharing | Recipient can no longer search, open or download that file. |
| Open Mi cuenta | Update the visible name; inspect own sessions and confirm before closing one or all others. Another member's session remains active. |
| Use a phone and keyboard | Menu, search, forms and drawers remain usable; Escape closes an idle drawer and focus returns to its trigger. |
| Add to the home screen, if the browser offers it | HomeAtlas opens at the same origin and requires the server and private network connection. |

Mi cuenta is in the avatar menu; username and PIN controls remain under **Mi acceso** on that page. Session management covers the current household, displays the authentication method and activity, and does not collect an IP address or identify physical devices. Closing a session does not remove its PIN binding: deactivate that separately in Mi acceso. Sessions expire after 30 minutes idle or 12 hours maximum.

Search URLs may appear in browser history or in links you share. Share only queries you intend to disclose; receiving a URL never grants access to its results. Responses are discarded when the session or permission context changes.

Installation availability depends on the browser and platform. The manifest uses the existing HomeAtlas icon. No service worker or offline document cache is installed. Installation does not enable background synchronization, offline access or bypass authentication. See [browser installation requirements](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Operator checks

1. Record the installed release, binary/package checksums and pilot start date. Confirm CI and the manual full suite pass on the intended revision.
2. Restart the service in an agreed maintenance window and verify documents, metadata and access remain intact. Read [interruption recovery](../deployment/crash-recovery.md) before investigating recovered batches.
3. Export an encrypted household backup, download it outside the VM and retain its exact plugin installer. In a separate clean data directory, install that package and restore the backup. Log in, compare original hashes and check the second member's access. Sessions, PIN bindings and SMTP/S3 configuration must be configured again.
4. Verify a new main deployment through the existing Tailscale pipeline. Exercise a failing update/rollback using disposable data and a separate service, not by interrupting the family's only installation. Local rollback snapshots do not replace off-machine encrypted backups.

## Feedback and exit criteria

Run for seven days with both people completing their tasks. Record date, release, device/browser, task, expected/actual behavior, severity and a sanitized reproduction. Ask whether anything needed explanation or assistance; distinguish independent completion from assisted completion.

V0.1 acceptance requires both people to confirm the core tasks, successful off-machine recovery, no unresolved access leak or data-loss issue, and documented decisions for remaining usability problems. Any leak, lost original or unrecoverable archive blocks closure. Technical/browser tests with synthetic users do not count as this human validation. Keep the project experimental until those results are reviewed.
